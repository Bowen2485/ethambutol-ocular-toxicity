# MR 数值的三个代际 —— 同一对暴露-结局有三个不同估计

> 记录时间：2026-10-16
> 起因：处理"稿件报 1.026/150–186，pooled 为 1.054/115"这一口径问题时，
> 逐个文件回溯，发现同一对"胱抑素 C → 视神经炎"在项目里有 **三个**不同的估计，
> 分别来自三代分析；稿件把它们混在了一句话里。
> 本文只记录可复核的事实，结论与处理方案在末节。

---

## 一、三个估计，三个来源

| 来源文件 | 修改时间 | n_snp | OR (95% CI) | q | 备注 |
|---|---|---|---|---|---|
| `results/mr_opengwas_results.csv` | **2026-10-16 15:15** | 115 | 1.054 (0.886–1.254) | 0.958 | 当前面板（60 行，29 列） |
| `results/mr_supplementary_results.csv` | 2026-10-14 18:39 | 162 | 1.035 (0.876–1.224) | 0.895 | 肾功能专项（18 行） |
| `tables/Table8_mr.csv` | — | 146 | **1.026 (0.865–1.216)** | 0.994 | ← 稿件引用的就是这个 |

**稿件正文（英文版第 1257 行、中文版第 645 行）写的是 1.026 (0.865–1.216)**，
即 Table 8 的值；但同一句里的"150–186 个工具变量"和"q ≥ 0.87"都来自
`mr_supplementary_results.csv`（151/162/186，q 最小 0.8695 ≈ 0.87）。
一个句子里同时用了两份文件，而 Table 8 的两个数字（146、q=0.994）都没被用上。

## 二、Table 8 是怎么变成孤儿的

`src/make_tables.py` 第 211 行规定 Table 8 的来源：

```python
t8 = read(RESULTS / "mr_opengwas_results.csv")
```

而 `results/mr_opengwas_results.csv` 在 **10-16 15:15 被重新生成过**：
从 13 行 27 列变成了 60 行 29 列，新增 `body_mass_index`（阳性对照）、
`smoking_initiation`、`cigarettes_per_day`、`HbA1c`、`alcohol_drinks_week`、
`zinc_supplement` 六个性状，并把 T2D 从单一估计重算为逐结局估计。

`Table8_mr.csv` 没有跟着重算，它仍是 10-13 版文件的副本（13 行、27 列，
列顺序与 10-16 版完全不同）。**所以 Table 8 相对它自己的生成器是过期的。**

## 三、稿件里"面板"那些数字追的是新文件，只有 T2D 例外

逐项对照 10-16 版面板文件与稿件：

| 稿件表述 | 10-16 面板文件 | 一致？ |
|---|---|---|
| BMI **266** 个工具变量（阳性对照） | 266 | ✅ |
| 吸烟启动 **32** 个工具变量 | 32 | ✅ |
| 每日吸烟量 **14** 个工具变量 | 14 | ✅ |
| BMI → 视神经炎阳性对照检出效应 | OR 1.680 (1.265–2.231)，q = 0.020 | ✅ |
| T2D → 视神经炎 **OR 1.094 (0.940–1.274)，57 个工具变量** | **OR 1.099 (0.942–1.284)，54 个工具变量** | ❌ |

**T2D 那一句仍引用已删除缓存算出的旧值。** `docs/待修正_MR缓存删除后的一致性.md`
第一节列出的必须删除重算的那一行，正是这个 1.094/57；
该文档第五节写明"重跑完成后……用新数字替换"。重跑已完成（10-16 版 54 个工具变量，
六个结局各自不同估计），**但这句还没有替换**。

## 五、需要决定的一件事（已定，见第六节）

肾功能专项（151/162/186，q ≥ 0.87）**不属于 Table 8**：
Table 8 是主面板（BMI、吸烟、T2D 等），而它的 q 最小为 0.0203（BMI 阳性对照），
"全部 q ≥ 0.87"在主面板里根本不成立。所以稿件那句 `(all q ≥ 0.87; Table 8)`
无论用哪个 OR 都是引错的。

三个可选做法：

1. **把 supplementary 的 18 行做成补充表（Table S1）**，肾功能那句改引 Table S1；
   同时按现行面板重算 Table 8、替换 T2D 数字、同步仓库。← 结构最清楚
2. **不新增表**，肾功能那句改引 `results/mr_supplementary_results.csv`（Frontiers 允许
   正文引数据文件），其余同上。
3. **把两组结果并入一张 Table 8**，正文注明分组来源（肾功专项 vs 主面板）。
   一张表里两种校正口径，读者容易误读，不推荐。

无论选哪个，T2D 数字替换、Table 8 重算、仓库同步这三件事都要做。

**已选定方案 1（2026-10-16）并执行完毕。**
